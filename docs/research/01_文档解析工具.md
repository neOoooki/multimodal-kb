## 二、逐个要点

**MinerU 4.x（重点）**
- **1.x / 2.x / 3.x / 4.x 演进**：1.x、2.x 时代输出 `content_list.json` / `middle.json`（字段 `type`/`text_level`/`img_path`/`img_caption`/`table_caption`/`page_idx`/`bbox`）；2.0 起转 VLM（MinerU2.5），3.1 换许可证并支持 PPTX/XLSX，4.0 重做为"四档 tier（flash/basic/standard/advanced）+ 统一文档模型"，输出改为 `docvortex.middle` / `structured_content` / `Content List V1&V2`。**4.0 明确不兼容旧 JSON**，老结果需重新解析（[迁移指南](https://opendatalab.github.io/MinerU/reference/migration_4/)、[输出契约](https://opendatalab.github.io/MinerU/reference/output_files/)、[Changelog](https://opendatalab.github.io/MinerU/reference/changelog/)）。
- **reading order 与图片位置**：有。数组顺序即阅读顺序，块级 `bbox` + `page_idx`（0 基）齐全；PDF 还输出 `extensions.docvortex_layout`（页宽高）。
- **图片**：裁成独立文件，命名规则见官方文档（`images/page_{page_idx}_{parent_type}_{parent_index}.{ext}`）；图注与图在 **同一个 item** 内，锚定关系天然正确。
- **跨页/层级短板**：只有 `text_level`（正整数表示标题层级）这种弱信号，**不直接给章节树**；跨页正文块也不会自动合并（跨页表格 2.6/2.7 起支持）。需要自己在 content_list 上按 `text_level` 建栈。
- **许可证**：MinerU Open Source License = Apache 2.0 + 附加条款：MAU > 1 亿 或 月收入 > 2000 万美元需单独商用许可；**对外提供在线服务必须显著标注使用了 MinerU**（[LICENSE.md](https://github.com/opendatalab/MinerU/blob/master/LICENSE.md)）。对教材项目无实质障碍。

**Docling（IBM，LF AI & Data 托管）**
- `DoclingDocument`：`texts`/`tables`/`pictures` + `body`/`furniture`/`groups` 树，**阅读顺序就是 `body` 树的子节点顺序**；每个 item 带 provenance（bbox + 页码）。标题层级默认全是 level 1，需显式开启 **heading hierarchy** 阶段（会用书签→编号→字号三条信号还原 `1.`/`1.1`/`(a)` 层级，默认关闭），层级会写进 Markdown `#` 与 DocTags，**并成为 hierarchical chunker 附在每个 chunk 上的 heading path**（[DoclingDocument](https://docling-project.github.io/docling/concepts/docling_document/)、[PDF heading levels](https://docling-project.github.io/docling/usage/heading_levels/)）。
- **对第 3 点（章节级上下文）最友好**：`HierarchicalChunker` / `HybridChunker` 直接在文档树上切块，自动附带标题路径与 caption，`merge_peers` 可合并同标题下的碎块（[Chunking](https://docling-project.github.io/docling/concepts/chunking/)）——这正好治"列表被切碎"。
- **中文风险（未完全验证）**：社区有 GB/T 标准 PDF + tesseract `chi_sim` 仍输出乱码 CID 的 issue（[#3582](https://github.com/docling-project/docling/issues/3582)）；缓解手段是换 RapidOCR / SuryaOCR / VLM pipeline（GraniteDocling 258M）。中文教材建议先做小样本实测。
- 许可 MIT，Python/CLI/`docling-serve`/MCP 全套，本地可跑，CPU 可用。

**Marker 2.x（datalab）**
- JSON 是页面为根的树，每个子块带 **`section_hierarchy`**（`{"1": "/page/10/SectionHeader/1"}` 形式），这是**开箱即用最接近"块→所属章节"**的设计；还有 `--output_format chunks`（扁平块列表，专为 RAG 切块）。metadata 提供 `table_of_contents`（标题+heading_level+page_id+polygon）。
- 图片随 Markdown 存盘，JSON 里 `images` 为 base64；`Figure`/`Caption` 是独立块类型需自行配对。
- 官方 olmOCR-bench：balanced 76.0（电子版 83.5），高于 MinerU pipeline 72.7 与 docling 50.3（[README 基准表](https://github.com/datalab-to/marker)）——**注意这是厂商自测**。2.0 大改：默认走 Surya VLM 推理服务器。
- **许可要点**：代码 Apache 2.0，但**模型权重是 modified OpenRAIL-M，仅对研究/个人/融资或营收 <500 万美元的初创免费**，超出需商业授权（同上 README；[Surya README](https://github.com/datalab-to/surya)）。商用项目要注意。

**Unstructured（hi_res）**
- 输出是扁平 `Element` 列表：`type`（Title/NarrativeText/ListItem/Table/Image…）+ `metadata`（`page_number`、`coordinates`（hi_res 策略）、`parent_id`、`languages`、`text_as_html`）（[Document elements and metadata](https://docs.unstructured.io/open-source/concepts/document-elements)）。
- **没有 heading level / 章节树**（`parent_id` 只是元素父子，例如 Table→它的单元格，不是章节归属），因此"整节召回"要自己按 Title 元素做归并。图片可用 `extract_image_block_types` 抽 base64（[how-to](https://docs.unstructured.io/open-source/how-to/extract-image-block-types)），图注关联较弱。
- hi_res 版面模型对英文文档最稳，中文建议配 PaddleOCR 做 OCR agent。适合已有 pipeline 想快速接现成元素体系，不适合做精细中文教材。

**olmOCR（AllenAI）**
- 定位是 **linearization**：把 PDF 拍平成干净 Markdown/纯文本（去页眉页脚、按自然阅读顺序），**不输出块类型、层级、bbox、图片**，也不给图注锚定。v0.4.0（2025-10-21）olmOCR-bench 82.4，但**面向英文**，中文未验证。
- 需 GPU（≥12GB VRAM，7B VLM，Docker 镜像约 30GB），Apache 2.0。**对本项目只能当"高质量中文 OCR 备用方案"，不能作为结构化数据源。**

**补位选手**
- **PP-StructureV3（PaddleOCR 3.7.0）**：23 类中文版面标签（含 `doc_title`/`paragraph_title`/`figure_title`/`table_title`/`figure_caption`），支持多栏阅读顺序恢复、表格 SLANeXt、公式识别，`save_to_json` / `save_to_markdown` 一步到位（[官方文档](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/PP-StructureV3.en.md)）。**中文教材图像归属错乱时最值得用它交叉校验版面。** 但它不输出标题层级数值、不建章节树。
- **Surya 2.x**：`blocks[].label` + `reading_order`（0 基 `position`）+ `bbox`，`SectionHeader`/`Caption`/`Picture` 分离；91 语种内测中文 82.5（[README](https://github.com/datalab-to/surya)）。可作为 Marker 的底层，也可单独当版面+阅读顺序引擎。
- **Grobid**：TEI XML 有真正的 `div`/`head` 章节树和 `<figure>` caption，但**只为英文学术论文设计**，中文教材不适用（[Grobid 文档](https://grobid.readthedocs.io/en/latest/)）。
- **Nougat**：已停更（0.1.17，2023-10），不建议纳入选型。

## 三、针对四个具体问题的能力评估

**问题 1：切分粒度粗、跨页硬截断、列表被切碎**
- 最好：**Docling**（HierarchicalChunker/HybridChunker 在文档树上切、同标题碎块可 merge，天然不跨标题乱切）；**Marker**（`chunks` 格式 + `section_hierarchy`，块自带章节归属）。
- 次之：**MinerU**（给块级 bbox+page_idx，但需要你自己"按标题建栈 + 跨页按标题合并"；跨页表格 2.6+ 已支持自动合并）。
- 差：Unstructured（扁平元素，需自建归并）、olmOCR（纯文本，无从谈粒度）。

**问题 2：图像归属错乱**
- 最好：**MinerU**（图与 `image_caption`/`image_footnote` 在同一 item，且带 `page_idx`+`bbox`，可直接验证归属）；**PP-StructureV3**（版面里 figure 与 figure_caption 是独立类，可按坐标就近配对，中文版面最准）。
- 次之：Docling（PictureItem + caption 引用 + provenance 坐标）、Surya（Picture 与 Caption 分块 + 坐标配对）。
- 差：Marker（图在 JSON 里是 base64 字典，caption 需自行配对）、olmOCR（完全不输出图）。

**问题 3：需要章节级上下文（整节召回）**
- 最好：**Docling**（heading hierarchy + hierarchical chunker 的 heading path，原生 parent-child）；**Marker**（`section_hierarchy` 直接给"这个块属于哪个 SectionHeader"）。
- 可行但需自研：**MinerU**（用 `text_level` 建栈——LightRAG 的 [MinerU IR builder](https://github.com/HKUDS/LightRAG/blob/main/lightrag/parser/external/mineru/ir_builder.py) 就是这个思路：`text_level>0` 开新块，其余 item 合并进当前块，并保留 `parent_headings`）。
- 做不到：Unstructured、olmOCR、PP-StructureV3（均无层级数值）。

**问题 4：文本与图片都能被正确检索**
- 需要"图 → 图注/所属小节"的双向元数据。**MinerU + 图注 + 章节路径**，或 **Docling（PictureItem + heading path）**，都可以给每张图打上 `{章节路径, 页码, bbox, 图注}` 后入库；再用 VLM 为图生成描述文本（Docling 有 picture description 示例，MinerU 3.1+ 支持 chart/image analysis）补齐图的文本侧召回。

## 四、推荐组合

**首选（中文教材、本地部署、商用友好）：MinerU 4.x（standard 档）为主解析器 + 自建章节栈**
1. `tier=standard` 解析，取 `content_list`（含 `text_level`/`bbox`/`page_idx`/`img_path`/`image_caption`）；
2. 后处理按 `text_level` 建 heading 栈、生成 `section_path`，把同 `section_path` 的相邻块（含跨页）合并为父块，实现 parent-child 入库；
3. 图用 `img_path` + 同 item 的 caption + `section_path` + `page_idx` 绑定；
4. 中文版面/表格存疑的页，用 **PP-StructureV3** 交叉校验。

**备选 A（想少写代码、要现成章节树）：Docling 2.13x**
开启 `HeadingHierarchyOptions(enabled=True, generate_parsed_pages=True)` + `HybridChunker`，直接拿到带标题路径与 caption 的 chunk。**但必须先用中文样本实测 OCR/版面质量**（GB/T 乱码 issue 尚未确认修复）。

**备选 B（GPU 充足、英文/多语为主、可接受权重新许可）：Marker 2.x balanced**，`section_hierarchy` + `chunks` 输出，落库改造量最小。

**不建议**：olmOCR 做主解析（无结构）、Nougat（停更）、Grobid（非中文学术论文场景）、Unstructured hi_res 主攻中文教材。

**⚠️ 未验证项**：① Docling 在中文教材（含多栏/公式/图注）上的端到端质量——仅有社区 issue 侧面证据，无官方中文基准；② Marker 2.0 的 JSON 输出是否仍逐字保留 `section_hierarchy` 字段（README 描述基于 1.x 时期，2.0 大改后字段可能变化）；③ MinerU 4.0 的 Content List V2 是否与旧版 `content_list.json` 字段完全一致（官方只保证新协议自洽，旧字段以 LightRAG 适配器为间接证据）。
